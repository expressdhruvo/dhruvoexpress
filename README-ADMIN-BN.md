# Dhruvo Express — Decap CMS অ্যাডমিন গাইড (বাংলা)

সাইটে এখন আসল `/admin` CMS যুক্ত। আপনি লগইন করে **কোড না ছুঁয়েই** নিচের সবকিছু এডিট করতে পারবেন। সেভ করলে CMS সরাসরি আপনার GitHub রিপোজিটরিতে `content/*.json` ফাইল আপডেট (commit) করে; GitHub Pages কয়েক মিনিটের মধ্যে নতুন কনটেন্ট প্রকাশ করে।

---

## ১. CMS দিয়ে কী কী এডিট করা যাবে

| CMS-এর পেজ | যা যা বদলাতে পারবেন |
|---|---|
| **🛒 পণ্য → সব পণ্য** | প্রতিটি পণ্যের **দাম**, নাম, প্যাক/সাইজ, ক্যাটাগরি, সাব-ক্যাটাগরি, **ছবির ওপরের ট্যাগ (ব্যাজ)**, প্যাকের ওজন, ছবির path/alt/লেবেল। **নতুন পণ্য যোগ** ও **পণ্য মুছে ফেলা**—দুটোই। |
| **🗂 ক্যাটাগরি** | **নতুন মেইন ক্যাটাগরি যোগ**, নাম বদল, মুছে ফেলা; প্রতিটি মেইন ক্যাটাগরির ভেতরে **সাব-ক্যাটাগরি যোগ/এডিট/মুছা**। “সব পণ্য” বোতামটি সাইট নিজে তৈরি করে। |
| **⚡ ফ্ল্যাশ সেল** | অফার **চালু/বন্ধ**, কোন পণ্য, সেল-দাম, শেষ সময় (HH:MM:SS, বাংলাদেশ সময়), বাটনের লেখা। সময় শেষ হলে সাইট নিজেই অফার বন্ধ করে দেয়। |
| **⚙️ সাধারণ সেটিংস** | WhatsApp নম্বর, পেমেন্ট নম্বর, ইমেইল, এলাকা; হিরোর শিরোনাম/বিবরণ; উপরে ঘোরানো **টিকার আপডেট/অফার**; ডেলিভারি চার্জের স্ল্যাব; “সাইটে দাম দেখাবে কিনা”; ফুটার নোট। |
| **📝 সাইটের লেখা** | ৩টি সুবিধা, “৩ ধাপে অর্ডার”, **প্রশ্ন-উত্তর (FAQ)** যোগ/এডিট/মুছা, সার্ভিস/পণ্য/কভারেজ/যোগাযোগ সেকশনের শিরোনাম ও লেখা। |

**ছবির ট্যাগ (ব্যাজ) সম্পাদনা/মুছা:** পণ্যের `badge` ফিল্ডে লেখা বদলালেই ট্যাগ বদলাবে; **ফাঁকা করে দিলে ট্যাগটিই চলে যাবে** (ট্যাগ মুছে ফেলার উপায় এটিই)।

**ছবি:** CMS-এর মিডিয়া বাটন দিয়ে নতুন ছবি আপলোড করলে তা `assets/uploads/`-এ জমা হয় এবং সেখান থেকে path বসানো যায়।

## ২. অ্যাডমিন চালু করার ধাপ (একবারই করতে হবে)

### ধাপ A — রিপোজিটরি তৈরি ও ফাইল আপলোড
1. GitHub-এ নতুন রিপোজিটরি (যেমন `dhruvo-express`) তৈরি করুন, branch `main`। রিপোজিটরি **Public** রাখলে GitHub Pages ফ্রি।
2. এই ফোল্ডারের **সব ফাইল ও ফোল্ডার** আপলোড করুন (`index.html`, `app.js`, `styles.css`, `marketplace.css`, `terms.html`, `privacy.html`, `PHOTO-CREDITS.html`, `robots.txt`, `README-BN.md`, `README-ADMIN-BN.md`, **`admin/`**, **`content/`**, **`assets/`**)।
   - `cms-demo/` আপলোড করবেন না (এটি শুধু শেখার ডেমো)।
3. **Settings → Pages → Source: Deploy from a branch → Branch `main` / `/(root)`** → Save। কয়েক মিনিট পর সাইট লাইভ হবে: `https://YOUR-USERNAME.github.io/dhruvo-express/`

### ধাপ B — লগইন/অথেনটিকেশন (Netlify Identity + Git Gateway — সবচেয়ে সহজ)
GitHub Pages-এ সার্ভার নেই, তাই লগইনের জন্য Netlify-এর ফ্রি Identity সার্ভিস ব্যবহার করা হয়। সাইটটি যেখানেই থাকুক, অ্যাডমিন এইভাবে কাজ করে:

1. [netlify.com](https://www.netlify.com)-এ ফ্রি অ্যাকাউন্ট (GitHub দিয়ে লগইন)।
2. **Add new site → Import an existing project → GitHub** → আপনার `dhruvo-express` রিপোজিটরি সিলেক্ট করুন → Deploy (বিল্ড কমান্ড কিছু দিতে হবে না)।
3. সাইটের **Site configuration → Access & security → Identity → Enable Identity**।
4. **Identity → Settings → Services → Git Gateway → Enable** (এটি CMS-কে GitHub-এ commit করার অনুমতি দেয়)।
5. **Identity → Invite users** → নিজের ইমেইলে ইনভাইট পাঠান → মেইলে গিয়ে অ্যাকাউন্ট সেট করুন (পাসওয়ার্ড দিন)।
6. এখন যেকোনো জায়গা থেকে লগইন: `https://YOUR-USERNAME.github.io/dhruvo-express/admin/`
   - ব্যবহারকারী: আপনার ইমেইল, পাসওয়ার্ড: যেটা সেট করেছেন।

> Netlify সাইটটি শুধু লগইনের জন্য; ভিজিটররা আপনার GitHub Pages সাইটেই আসবেন। চাইলে Netlify সাইটের URL-ও ব্যবহার করতে পারেন—দুটোই একই রিপোজিটরি থেকে চলে।

### ধাপ C — বিকল্প: সরাসরি GitHub দিয়ে লগইন (ঐচ্ছিক)
Netlify-তে **Access & security → OAuth → Authentication providers → Install provider → GitHub** চালু করে GitHub OAuth app-এর Client ID/Secret বসিয়ে দিলে `admin/config.yml`-এ নিচের backend ব্যবহার করা যায়:

```yaml
backend:
  name: github
  repo: YOUR-USERNAME/dhruvo-express
  branch: main
  site_domain: YOUR-SITE.netlify.app
  base_url: https://api.netlify.com
```

## ৩. রোজকার কাজ — কোথায় কী করবেন

- **দাম বদল:** পণ্য → সেই পণ্যটি খুলুন → `দাম (টাকায়, শুধু সংখ্যা)` → Save → **Publish**।
- **নতুন মেইন ক্যাটাগরি:** ক্যাটাগরি → `ক্যাটাগরি` তালিকায় **Add** → `id` (ইংরেজি, যেমন `fresh`) + `label` (যেমন `তাজা বাজার`) → সাব-ক্যাটাগরি চাইলে তালিকায় Add → Publish। তারপর পণ্যের `category` ফিল্ডে ওই `id` বসান।
- **নতুন সাব-ক্যাটাগরি:** ওই মেইন ক্যাটাগরির `subcategories` তালিকায় Add → `id` + `label` → Publish। (সাব-ক্যাটাগরি বোতাম তখনই দেখাবে, যখন অন্তত একটা পণ্যে ওই `id` বসানো থাকবে।)
- **নতুন পণ্য:** পণ্য → তালিকায় **Add** → সব ফিল্ড পূরণ → Publish। `id` অবশ্যই ইংরেজি ও একক (যেমন `rice-nazirshail`)।
- **পণ্য মুছা:** পণ্যের ডানদিকে ট্র্যাশ আইকন → Publish।
- **ট্যাগ যোগ/মুছা:** পণ্যের `ছবির ওপরের ট্যাগ` ফিল্ড → লিখলে দেখাবে, ফাঁকা করলে মুছে যাবে।
- **ফ্ল্যাশ সেল:** ⚡ ফ্ল্যাশ সেল → `enabled` অন → `productId` (পণ্যের id), `salePrice`, `endTime` → Publish।
- **টিকার/দৈনিক আপডেট:** সাধারণ সেটিংস → `উপরে ঘোরানো আপডেট/অফার বার` → Add/এডিট।

**Save ≠ লাইভ:** CMS-এ Save করলে রিপোজিটরিতে commit যায়; GitHub Pages-এ দেখতে ১–২ মিনিট লাগতে পারে। তাড়াহুড়োয় কাজ না করলে ব্রাউজারে hard refresh (Ctrl+Shift+R) করুন।

## ৪. সীমাবদ্ধতা (জেনে রাখা ভালো)

- GitHub Pages-এ **কোনো ডেটাবেস/সার্ভার নেই**—তাই অর্ডার, কাস্টমার লিস্ট, স্টক বা পেমেন্ট CMS-এ জমা হয় না। অর্ডার এখনো **WhatsApp/ইমেইল**-এ আসে; চেকআউট শুধু WhatsApp-এ বার্তার খসড়া তৈরি করে।
- CMS-এর লেখা ভুল হলে (যেমন `id` মিল না থাকা) সাইট সেই অংশটি কেটে দেয়; সবসময় ডিফল্ট লেখা থেকে আলাদা করবেন না। পণ্যের `id` পরিবর্তন করলে সেই পণ্যের পুরনো কার্ট-এন্ট্রি মিলবে না।
- ডেলিভারি চার্জ/দূরত্ব এখনো WhatsApp-এ ম্যানুয়ালি নিশ্চিত হয়—তা CMS-এ আনতে চাইলে প্রথমে সাইটে কোড করে ফিচারটি যোগ করতে হবে, এরপর CMS-এ ফিল্ড যোগ করা যাবে।
- ছবি আপলোড করলে রিপোজিটরির আকার বাড়ে; বড় ছবি আগে WebP-তে বদলে নিন।

## ৫. পরবর্তীতে নতুন ফিচার যুক্ত করা যাবে?

**হ্যাঁ—দুই ধাপে:**

1. **কনটেন্ট/লেখা/তালিকা জাতীয় কিছু** (নতুন সেকশনের লেখা, নতুন তালিকা, নতুন FAQ, নতুন ব্যানার, নতুন অফার ফিল্ড): শুধু `content/*.json`-এ ফিল্ড যোগ করে `admin/config.yml`-এ সেই ফিল্ডটি লিখে দিলেই CMS-এ এডিট করা যায়। কোড লাগে না।
2. **নতুন ধরণের ফিচার** (যেমন: কুপন কোড, ডেলিভারি স্লট বুকিং, রিভিউ, স্টক ব্যাজ, মাল্টি-ইমেজ গ্যালারি): প্রথমে সাইটে একবার কোড করে ফিচারটি বানাতে হবে এবং এর ডেটা `content/*.json`-এ রাখতে হবে—তারপর `admin/config.yml`-এ ফিল্ড যোগ করলেই আপনি CMS থেকে এডিট করতে পারবেন।

**যা করা যাবে না (GitHub Pages-এর কারণে):** সার্ভার-সাইড অর্ডার স্টোরেজ, লগইন করা কাস্টমার অ্যাকাউন্ট, অটোমেটিক পেমেন্ট যাচাই, SMS/ইমেইল ট্রিগার, শিডিউল করা কাজ। এগুলো দরকার হলে Netlify Functions/Supabase-এর মতো ব্যাকএন্ড লাগবে—সেটি আলাদা করে বানানো সম্ভব।

## ৬. ফাইল মানচিত্র

```
admin/
  index.html     → CMS-এর UI (Decap CMS CDN থেকে লোড হয়)
  config.yml     → কোন ফাইলের কোন ফিল্ড এডিট করা যাবে, তার নকশা
content/
  products.json    → ১২টি পণ্য (দাম, ট্যাগ, ক্যাটাগরি, ছবি)
  categories.json  → মেইন + সাব ক্যাটাগরি
  flash-sale.json  → ফ্ল্যাশ সেলের অবস্থা
  settings.json    → WhatsApp/পেমেন্ট নম্বর, হিরো লেখা, টিকার, ডেলিভারি চার্জ
  sections.json    → সুবিধা, ধাপ, FAQ, সেকশন লেখা
assets/uploads/    → CMS থেকে আপলোড করা ছবি
```

**নিরাপত্তা:** `/admin` পেজে `noindex` আছে; লগইন ছাড়া কেউ কিছু এডিট করতে পারবে না। Netlify Identity-তে শুধুমাত্র ইনভাইট করা ইউজার থাকবেন—অপ্রয়োজনীয় “signup open” বন্ধ রাখুন (Identity → Settings → Registration preferences → **Invite only**)।
